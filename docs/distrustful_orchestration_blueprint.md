# Distrustful Local Agent Blueprint (16 GB Target)

## Module boundaries
- `gaia/gaia_core/distrustful_agent.py`
  - `DeterministicController`: code-driven FSM.
  - `EditIntent` + `DeterministicDiffEmitter`: selector/AST-aware edit path.
  - `WitnessLedger`: hash-chained JSONL + SQLite WAL index + CAS artifacts.
  - `ToolWitnessRunner`: authoritative tool execution witness logging.
  - `VerificationRunner`: deterministic verification order.
  - `InjectionSanitizer`: indirect prompt-injection defenses.
  - `RetryManager`: bounded retries + entropy cap.
  - `ApprovalTokenManager`: scoped approval tokens (HMAC).

## SQLite schema (WAL)
See `WITNESS_SQL_SCHEMA` constant. It creates `witness_records` with:
- chain metadata: `prev_hash`, `record_hash`
- tool witness columns: `tool_name`, `args_hash`, `exit_code`, output hashes, byte counts, truncation flags, timing
- provenance columns: `host_fingerprint`, `model_fingerprint`
- control columns: `verification_status`, `controller_decision`, `failure_class`

## Witness JSON schema
See `WITNESS_JSON_SCHEMA` constant.
- Required: `event_id`, `ts_utc`, `phase`, `prev_hash`, `record_hash`.
- Optional: hashes and metadata for tool outputs, verification, and controller decisions.

## EditIntent schema
See `EDIT_INTENT_JSON_SCHEMA` + `EditIntent` dataclass.
- Includes all required fields from the request:
  - `file_path`, `language`, `selector_kind`, `symbol_name`, `anchor_text`, `scope_hint`, `ast_path`, `replacement_snippet`, `postconditions`, `rationale_summary`.

## Controller/FSM design
States:
- `IDLE -> PLAN -> RESOLVE_EDIT -> SNAPSHOT -> VERIFY -> APPROVAL -> FINALIZE -> IDLE`
- Recovery path: `VERIFY (required failure after apply) -> ROLLBACK -> HALT`
- Any invalid transition is rejected by code.

Transitions are explicit and code-defined in `DeterministicController.TRANSITIONS`; no model decides routine transitions.

## Dirty-state model and rollback strategy
- Explicit session tracking (`DirtyStateTracker`) records:
  - `patch_check_passed`
  - `apply_patch_succeeded`
  - `working_tree_changed`
  - `rollback_snapshot_created`
  - rollback outcome flags
  - `pre_existing_dirty_state`
  - `agent_introduced_dirty_state`
- Snapshot strategy before patch apply:
  1. `git stash push --include-untracked -m gaia-agent-<session>`
  2. structured snapshot artifact fallback
- On required verification failure after apply:
  - execute deterministic rollback helper
  - verify with witnessed `git status --porcelain`
  - emit `rollback_succeeded`, `rollback_failed`, or `rollback_not_needed`
  - classify dirty rollback failure as `rollback_failed_dirty_repo`

## Deterministic diff emitter
- Input: validated `EditIntent`.
- Resolution order:
  1. AST (`python` symbol resolution with exact match) when possible.
  2. Scope-aware anchor/symbol fallback.
  3. strict uniqueness requirement.
- Output: unified diff generated by `difflib.unified_diff`.
- Ambiguity triggers `SelectorAmbiguityError` and halts.

## Tool witness wrapper
- All commands run through `ToolWitnessRunner.run`.
- Logs authoritative tool outputs with byte counts + hashes.
- Large output persisted to CAS (`artifacts/<sha256>.<suffix>`).
- Model claims are never used as proof.

## Approval token design
- Token body: `scopes`, `iat`, `exp`, `jti`.
- HMAC-SHA256 signed, URL-safe base64 encoded.
- `verify()` checks signature, expiry, and required scope.

## Retry manager
- Per-class budgets with hard global entropy cap.
- Supports jittered truncated exponential backoff only for retryable failures.
- Raises `RetryBudgetExceeded` to force escalation and prevent loops.

## Injection sanitizer
- Treats file/web/tool text as untrusted.
- Adds provenance prefix (`[UNTRUSTED:<source>]`).
- Flags high-risk patterns.
- Neutralizes fake tool call syntax and angle-bracket payload patterns.

## Verification runner
Order:
1. `git apply --check`
2. `git apply`
3. `git status --porcelain` (must show actual change)
4. `ruff check .` (optional)
5. `mypy .` (optional)
6. `pytest -q`
7. `bandit -q -r .` (optional strict mode)

Failure classes:
- deterministic: patch/check/change detection
- infra/tool: command unavailable/infra exit codes
- flaky/environmental: other verifier failures
- rollback/finalization additions:
  - `pre_existing_dirty_state_blocked`
  - `rollback_failed_dirty_repo`
  - `commit_finalization_failed`
  - `git_notes_failed`
  - `partial_finalization_failure`

## Memory profiling notes
Use `memory_profile_notes()` for built-in operator defaults:
- one active reasoning model at a time
- bounded retrieval (`k <= 8`, chunk cap)
- stream large outputs to CAS
- capped SQLite WAL
- keep_alive only for active reasoning windows

## End-to-end flow
1. Task received → FSM `PLAN`.
2. LLM proposes `EditIntent` (untrusted).
3. Schema validation + deterministic selector resolution.
4. Deterministic unified diff generation.
5. Snapshot phase creates rollback checkpoint + witness event.
6. Verification pipeline executes tools; all outputs witnessed.
7. On post-apply required failure, rollback executes before halt.
8. Sensitive operation requires scoped approval token.
9. Finalize with commit + git note metadata and verify both exist:
   - model + quantization + temperature + seed
   - prompt schema hash
   - witness tip hash
   - verification summary hash

## Provenance finalization flow
- `finalize_commit(...)` creates machine-labeled commit:
  - `chore(agent): apply witnessed patch for <task-id>`
- `build_provenance_note(...)` produces deterministic JSON note payload.
- `attach_git_note(...)` attaches structured provenance with witnessed tool call.
- `verify_finalization(...)` verifies:
  - commit exists
  - note exists
  - note `witness_tip_hash` matches expected finalization tip
- Commit success + note failure is classified as `partial_finalization_failure`.
